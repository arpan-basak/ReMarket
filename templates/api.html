DEVELOPER INTEGRATION

Connect CraftProof to ReMarket

When a certified item is purchased, ReMarket saves its certificate code and the buyer’s name. CraftProof can read that completed sale from ReMarket’s protected API and record the buyer as the new holder.

01 · OVERVIEW

How the connection works

  1. ReMarket records a purchase. A listing with a CraftProof certificate code becomes a completed order. ReMarket saves the code and buyer name at checkout.
  2. CraftProof reads the sale. Its server requests new sales from ReMarket using a shared API key. It can also request one order by ID.
  3. CraftProof updates the certificate. Its server finds the item by certificate code, checks the sale, and records the buyer name as the new holder.

CraftProof initiates the API request. ReMarket does not call a CraftProof transfer endpoint or update its ownership ledger.

02 · AUTHENTICATION

Set up access

The ReMarket server owner sets a long random secret in the REMARKET_SALE_API_KEY environment variable before starting the app. The same secret is given privately to the CraftProof server team.

# PowerShell, on the ReMarket server
$env:REMARKET_SALE_API_KEY = "YOUR_LONG_RANDOM_SECRET"
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000

Every sale request must include:

Authorization: Bearer YOUR_LONG_RANDOM_SECRET

Make these requests from the CraftProof backend, not browser JavaScript. Never place the secret in a public page or frontend bundle. The value of this server’s key is intentionally not displayed here.

Base URL seen by this page: {{ api_base }}. CraftProof needs a publicly reachable HTTPS ReMarket URL; 127.0.0.1 works only on the developer’s own computer.

To check that the ReMarket server is reachable, request GET {{ api_base }}/health. It returns {"status":"ok"} without an API key.

03 · REQUESTS

Endpoints

GET/api/v1/sales?after_id=0&limit=100

List completed sales that have a certificate code, oldest first. The response includes next_after_id. Use it as after_id on the next poll. limit must be 1–100 and defaults to 100.

GET {{ api_base }}/api/v1/sales?after_id=0&limit=100
Authorization: Bearer YOUR_LONG_RANDOM_SECRET
GET/api/v1/sales/RM-000001

Fetch one order by its ReMarket order ID. This also works for an order without a certificate, which will have certificate_code: null. Such orders do not appear in the list above.

GET {{ api_base }}/api/v1/sales/RM-000001
Authorization: Bearer YOUR_LONG_RANDOM_SECRET

04 · DATA FORMAT

Sale response

The list endpoint returns a sales array and a cursor. The single-order endpoint returns one sale object directly.

{
  "sales": [
    {
      "order_id": "RM-000001",
      "certificate_code": "KOODE0LL",
      "buyer_name": "Asha Rao",
      "status": "completed",
      "completed_at": "2026-10-14T12:00:00+00:00"
    }
  ],
  "next_after_id": 1
}

The certificate code and buyer name are saved when the purchase happens. No buyer or seller CraftProof ID is sent. ReMarket does not collect a transfer address because CraftProof’s current transfer request does not have an address field.

05 · PARTNER IMPLEMENTATION

What the CraftProof team builds

  • Store the shared ReMarket API key on the CraftProof server and poll the sale list, or fetch a known order ID.
  • Check that the order is completed, resolve certificate_code to the CraftProof item, and validate that this sale should change its ownership.
  • Record buyer_name as the new holder. CraftProof’s current transfer request supports to_name; its existing protected route uses an internal piece ID, so the certificate-code lookup belongs on the CraftProof side.
  • Save order_id as a unique import reference. If the same sale is polled again, do not transfer it twice. Keep failed order IDs for retry or review.

ReMarket also reads CraftProof’s public GET /api/verify/{code} endpoint to show certificate history on a listing. That read endpoint does not require a CraftProof login. View CraftProof’s API documentation ↗

06 · BEFORE GOING LIVE

Current limits

This is a demo marketplace. Its purchase button records an order without payment or physical handoff verification. The buyer’s ReMarket name is self reported, so it is not proof of identity. CraftProof must decide what validation is sufficient before changing a real certificate.

ReMarket exposes the sale API, but CraftProof has not yet connected its importer. A completed purchase will not automatically change the CraftProof owner until that partner work is done. The API is available in FastAPI’s interactive documentation.
